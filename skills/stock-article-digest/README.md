# stock-article-digest — 股市文章整理

[English](README.en.md)

丟一篇台美股文章給 AI，它會整理成一份格式固定的 Markdown 筆記存起來。來源可以是新聞、部落格、PTT 股版、法說會整理文，給網址、給存下來的網頁原始碼、直接貼純文字都行。

筆記開頭是程式讀得懂的 YAML front matter，列出提到的公司代號、產業和標籤。格式固定，存了幾百篇之後，一行指令就能找出所有提過雙鴻的筆記：

```bash
grep -l 'TWO:3324' stock-notes/*.md
```

這份 skill 的規則多半在防同一件事：模型自己編。編出來的 EPS、記錯的代號，混進真資料就挑不出來了。所以代號一律拿官方清單核對，財務數字只收原文寫的，AI 自己補的公司會標「補充」。

**你可能會反對的三件事**：

- **它不加分析，也不給建議。** 筆記只記作者說了什麼。自問自答、延伸閱讀、投資建議都不寫，寫了檢查腳本會擋。唯一的例外是概念股表可以補原文沒提的公司，但會標成「補充」。
- **標籤只能用固定清單。** 清單在 `references/tag-vocabulary.md`，目前有 45 個產業、185 個標籤。清單裡沒有的詞可以用，但要另外列進 `new_tags`，等你決定收不收。這樣做比較麻煩，換來的是搜 `HBM` 不會漏掉寫成「高頻寬記憶體」的那幾篇。
- **要連網路才核對得了代號。** 官方清單第一次用時下載，之後每天更新一次。離線時沿用舊的快取；連快取都沒有，代號就沒辦法核對，檢查結果會提醒你。

## 安裝

```bash
npx skills add nickolaslin33/agent-skills@stock-article-digest
```

需要 Python 3。三支腳本只用標準函式庫，不用另外裝套件。

裝好之後不用設定。丟股市文章的網址、說「整理這篇」「這篇在講什麼」就會觸發，也可以直接打 `/stock-article-digest`。

## 兩種模式

| 模式 | 怎麼觸發 | 產出 |
|---|---|---|
| `digest` | 預設 | 核心摘要 3 到 5 點，其他段落精簡 |
| `full` | 訊息裡寫「完整轉換」 | 核心摘要不限點數，另加一段「逐段整理」，照原文順序留下每個論點、數字和舉例 |

## 筆記長什麼樣子

每份筆記有四個固定段落：核心摘要、產業鏈與概念股、財務數據、市場情緒與留言。原文沒提到的段落不刪，寫「本文未提及」，程式才分得出是沒內容還是漏寫。

下面範例的代號是真的，數字和事件是虛構的：

```markdown
---
date: 2026-03-02
date_from: json-ld:datePublished
processed: 2026-03-03
title: "散熱族群法說會整理：液冷滲透率上修"
source: https://example.com/news/12345
mode: digest
tickers:
  - {code: "TW:3017", name: 奇鋐, origin: 原文, verified: listed, industry: 電腦及週邊設備業}
  - {code: "TWO:3324", name: 雙鴻, origin: 原文, verified: listed, industry: 其他電子業}
  - {code: "US:NVDA", name: 輝達, origin: 補充, verified: listed}
sectors: [散熱, AI伺服器]
tags: [液冷, 法說會]
new_tags: []
---

## 核心摘要

- 兩家散熱廠都上修今年液冷產品的營收占比，奇鋐 [TW:3017] 從兩成調到三成。

## 財務數據

| 公司 | 項目 | 數值 | 期間 | 原文依據 | 備註 |
| --- | --- | --- | --- | --- | --- |
| 雙鴻 [TWO:3324] | 毛利率 | 25.1% | 2025Q4 | 「第四季毛利率 25.1%」 | 季增 1.2 個百分點 |
```

財務表每一列都要貼一小段原文當依據。原文沒寫的季度和 EPS，AI 就算記得也不准填。

`date` 是文章的發布日期，整理那天記在 `processed`。找不到發布日期就寫 `unknown`，不會拿今天去填，不然之後分不出哪篇是舊文。

## 代號怎麼核對

| 市場 | 寫法 | 核對來源 |
|---|---|---|
| 上市 | `TW:2330` | TWSE OpenAPI |
| 上櫃 | `TWO:3324` | TPEx OpenAPI |
| 興櫃 | `TWE:3097` | TPEx OpenAPI |
| 美股 | `US:NVDA` | SEC `company_tickers.json` |
| 日股、韓股、港股 | `JP:8035`、`KR:005930`、`HK:0700` | 沒有官方清單，只檢查格式 |

每家公司另外標 `verified`，說明代號可以信到什麼程度：

| `verified` | 意思 |
|---|---|
| `listed` | 官方清單查得到，簡稱也對得上 |
| `delisted` | 已下市，寫的是下市前的代號 |
| `not-found` | 查不到，代號寫 `?`，例如 `TW:?`。未上市公司也寫這個 |
| `format-only` | 那個市場沒有官方清單，或是台股 ETF，只檢查格式 |

台股的上市、上櫃最容易搞混。雙鴻是上櫃的 `TWO:3324`，寫成 `TW:3324` 檢查腳本會直接指出市場寫錯。官方簡稱常寫「臺」（臺慶科），查詢時「台」「臺」都認得。

終止上市有官方清單可以核對。上櫃公司下櫃沒有公開清單，這類代號檢查時會提醒你自己確認。

## 存檔與檢查

筆記存到 `$STOCK_DIGEST_DIR`。沒設的話，存到目前工作目錄下的 `stock-notes/`。檔名是 `<日期>-<標題前 30 字左右>.md`。

存完 AI 會跑 `validate.py`。它檢查的項目包括：

- front matter 每個欄位都在，寫法對
- 每個代號都在官方清單上，簡稱和產業別也對得上
- 本文出現的每個 `[市場:代號]` 都列在 `tickers`，`tickers` 裡的每家也都在本文出現過
- 標籤都在清單裡，清單外的都列進 `new_tags`
- 財務表每列都有原文依據
- 沒有「延伸閱讀」這類不該有的段落

有錯誤 AI 會改到通過為止。有提醒（例如查不到的代號、新標籤）會在回覆裡轉告你。

## 自己跑腳本

```bash
# 查代號，可以一次查好幾個，名稱或代號都行
python3 scripts/tickers.py lookup 台積電 雙鴻 NVDA 3324

# 立刻重抓官方清單
python3 scripts/tickers.py update

# 抽網頁內容，輸出 JSON
python3 scripts/extract.py https://example.com/news/12345
python3 scripts/extract.py saved-page.html

# 檢查一份筆記，通過 exit 0，有錯 exit 1
python3 scripts/validate.py stock-notes/2026-03-02-散熱族群法說會整理.md
```

| 環境變數 | 用途 | 預設 |
|---|---|---|
| `STOCK_DIGEST_DIR` | 筆記存放的資料夾 | `./stock-notes/` |
| `STOCK_DIGEST_CACHE` | 官方清單快取的位置 | `~/.cache/stock-article-digest/` |

有些 Python 沒接上系統的憑證庫，HTTPS 會驗證失敗。腳本這時會改用 `curl` 下載，不會關掉憑證驗證。

## 限制

- **美股清單只有英文名。** 「美光」要用 `Micron` 或 `MU` 查。AI 會自己換，你手動查的時候要注意。
- **留言常常抓不到。** 很多網站的留言是頁面載入後才補上的，用網址抓拿不到。要留言的話，在瀏覽器展開留言後另存網頁原始碼，再把那個檔案給 AI。
- **需要登入的頁面抓不到。** 一樣在瀏覽器登入後另存網頁原始碼。
- **只收台、美、日、韓、港五地。** 中國 A 股、歐股等其他市場的公司不列代號，本文寫公司名並註明在哪上市。
- **官方產業別很粗。** 奇鋐是散熱廠，官方分類卻是「電腦及週邊設備業」。所以 `industry` 只擋得住離譜的錯，例如把食品股當成散熱股。

`SKILL.md` 是給 AI 看的完整流程，包含每個欄位的寫法、查不到代號時怎麼處理、檔名規則。
