# 股市文章摘要

把一篇股市文章變成一份格式固定的 Markdown 檔，存起來。格式固定是為了之後能寫程式整批掃：哪些文章提過 `TWO:3324`、上個月有幾篇在講 `HBM`。

這份 skill 的規則多半在防同一件事：**股市資料最怕模型自己編**。編出來的 EPS、記錯的代號，混在真資料裡就再也挑不出來。所以能交給程式查的就交給程式，查不了的就標清楚是誰說的。

## 流程

### 1. 抽內容

輸入是網址或存下來的網頁原始碼，都交給 `extract.py`：

```bash
python3 scripts/extract.py <網址或 HTML 檔>
```

它回傳 JSON：標題、發布日期、正文、留言、圖片說明，以及 `warnings`。使用者直接貼純文字就跳過這步，自己讀。

- `published` 是 null 的話，正文裡有明寫日期（像 PTT 的「時間 Tue Oct 13 18:44:51 2026」）就用它，`date_from` 寫 `text`；正文也沒有就寫 `unknown`。**不要填今天**，處理日期另外記在 `processed`，兩個混在一起之後就分不出哪篇是舊文。
- `comments` 是空的就照 `warnings` 講的，在留言段落寫「原文未附留言」，並在回覆裡告訴使用者：要留言就在瀏覽器展開後另存網頁原始碼。不要從正文推測留言區在說什麼。

### 2. 判斷模式

使用者的訊息有「完整轉換」就是 `full`，否則是 `digest`。

- `digest`：核心摘要 3 到 5 點，其他段落精簡。
- `full`：核心摘要不限點數，並在核心摘要後面多一段 `## 逐段整理`，照原文順序把每個論點、數字、舉例都留下來。

### 3. 查代號

把文章提到的每家公司，連同你打算補充的公司，一次查完：

```bash
python3 scripts/tickers.py lookup 台積電 雙鴻 NVDA 美律
```

美股清單只有英文名，「美光」要查成 `Micron` 或 `MU`。

照查詢結果寫代號，不要憑記憶。台股代號模型常常記錯，上市（`TW`）和上櫃（`TWO`）也容易搞混，例如雙鴻是上櫃的 `TWO:3324`。

| 狀況 | 代號寫法 | `verified` |
|---|---|---|
| 查到唯一一筆 | 照查詢結果，例如 `TW:2330` | `listed` |
| 查到多筆 | 依文章脈絡挑一筆；挑不出來就問使用者 | `listed` |
| 查不到 | `TW:?`（市場照你的判斷） | `not-found` |
| 日股、韓股、港股、台股 ETF | 依格式寫，例如 `KR:005930`、`JP:8035`、`TW:0050` | `format-only` |

台股的 `industry` 照查詢結果的官方產業別填。官方分類很粗（奇鋐是散熱廠，官方卻是「電腦及週邊設備業」），所以它只能擋掉離譜的錯，例如把食品股當成散熱股。

### 4. 寫摘要

照下面的「輸出格式」寫。幾條規則和它們的理由：

- **財務數字只收原文寫的。** 每一列都要在「原文依據」貼一小段原文。原文沒有的季度、沒有的 EPS 就不要寫，就算你記得也不要。整篇沒有數字就寫「本文未提及」。這張表會被程式讀去做比較，一個記憶裡的數字混進來，整張表就不能信了。
- **補充的公司要標。** 概念股表可以補原文沒提的公司，但「來源」欄要寫 `補充`，front matter 的 `origin` 也寫 `補充`。補之前先查代號，看看官方產業別合不合理。這樣之後寫程式時，才能只挑原文提到的公司。
- **只整理原文，不加自己的東西。** 不要自己出題自答、不要寫投資建議、不要附延伸閱讀或搜尋關鍵字。這份檔案是文章的紀錄，混進你的分析，之後就分不清哪些是作者說的。唯一的例外是概念股表的 `補充`，因為有標記。
- **圖片只能推測。** 只能根據 `extract.py` 給的圖片說明和上下文推測，段落標題寫「推測」，不要描述你沒看到的圖表數字。
- **標籤用固定清單。** `sectors` 和 `tags` 只能用 `references/tag-vocabulary.md` 裡的字。清單裡沒有合適的，可以用新標籤，但要同時列進 `new_tags`。
- **語氣**：專業、客觀、直接。不要寒暄、不要免責聲明、不要在結尾問「還需要什麼」。

### 5. 存檔並檢查

存到 `$STOCK_DIGEST_DIR`，沒設就存到目前工作目錄下的 `stock-notes/`；使用者指定別的資料夾就照他的。

檔名：`<date>-<slug>.md`。`date` 是 `unknown` 時改用 `processed`。`slug` 取標題前 30 個字左右，空白和 `/ \ : * ? " < > |` 換成 `-`。同名檔案已經存在就加 `-2`、`-3`。

存好之後跑：

```bash
python3 scripts/validate.py <剛存的檔案>
```

有 `ERROR` 就照訊息改，改到 `OK` 為止。`WARN` 不用改，但要在回覆裡轉告使用者，例如查不到的代號、新標籤。

### 6. 回覆

把摘要全文貼在回覆裡，最後一行寫存檔路徑。有 `WARN` 或 `extract.py` 的 `warnings` 就在路徑前面列出來，一句話一條。

## 輸出格式

front matter 只接受下面這種寫法，`validate.py` 用一個小型解析器讀它，不認得的寫法會被擋：

- 每個鍵一行，鍵名照抄。
- `title` 一律用雙引號包起來，標題裡的 `"` 寫成 `\"`。標題常有冒號，不包會讓 YAML 讀錯。
- `tickers` 每家公司一行，用 `{...}` 寫在同一行。
- 清單用 `[a, b]`，空清單寫 `[]`。
- 標籤**不加** `#`。YAML 裡 `#` 是註解符號，`- #半導體` 會整行消失。

下面範例的代號是真的，文章、數字和事件都是虛構的，只用來示範格式。

```markdown
---
date: 2026-03-02
date_from: json-ld:datePublished
processed: 2026-03-03
title: "散熱族群法說會整理：液冷滲透率上修"
source: https://example.com/news/12345
mode: digest
tickers:
  - {code: "TW:3017", name: 奇鋐, origin: 原文, verified: listed, industry: 電腦及週邊設備業}
  - {code: "TWO:3324", name: 雙鴻, origin: 原文, verified: listed, industry: 其他電子業}
  - {code: "US:NVDA", name: 輝達, origin: 補充, verified: listed}
sectors: [散熱, AI伺服器]
tags: [液冷, 法說會]
new_tags: []
---

## 核心摘要

- 兩家散熱廠都上修今年液冷產品的營收占比，奇鋐 [TW:3017] 從兩成調到三成。
- ……

## 產業鏈與概念股

| 關鍵技術/元件 | 關聯產業 | 相關公司 | 來源 | 關聯說明 |
| --- | --- | --- | --- | --- |
| 水冷板 | 散熱 | 奇鋐 [TW:3017] | 原文 | 法說會表示水冷板產能年底倍增 |
| GPU | 半導體 | 輝達 [US:NVDA] | 補充 | 液冷需求主要來自其高功耗 GPU 機櫃 |

## 財務數據

| 公司 | 項目 | 數值 | 期間 | 原文依據 | 備註 |
| --- | --- | --- | --- | --- | --- |
| 雙鴻 [TWO:3324] | 毛利率 | 25.1% | 2025Q4 | 「第四季毛利率 25.1%」 | 季增 1.2 個百分點 |

## 市場情緒與留言

- **作者回覆**：……
- **留言重點**：看多的理由……；看空或存疑的……
```

可選段落，有內容才寫：

- `## 逐段整理`：只有 `full` 模式，接在核心摘要後面。
- `## 圖片解讀（推測）`：放在財務數據後面。`extract.py` 有抓到和文章有關的圖片說明時才寫。它會漏抓到側欄或推薦文章的縮圖，看起來跟正文無關的就略過。

沒有內容的必要段落不要刪，寫一句說明：產業鏈和財務寫「本文未提及」，留言寫「原文未附留言」。少了段落，程式就分不清是沒內容還是漏寫。

本文裡每個 `[市場:代號]` 都要出現在 `tickers`，`tickers` 的每一家也都要在本文出現至少一次。

## 腳本與環境

- 三支腳本只用 Python 標準函式庫。
- `tickers.py` 把官方清單快取在 `$STOCK_DIGEST_CACHE`（預設 `~/.cache/stock-article-digest/`），超過一天自動重抓。網路不通時沿用舊快取；連快取都沒有，`validate.py` 會在 `WARN` 說哪些代號沒核對到，這時要在回覆裡講明。
- 有些 Python 安裝沒接上系統憑證庫，HTTPS 會驗證失敗，腳本會自動改用 `curl` 抓，不會關掉憑證驗證。
