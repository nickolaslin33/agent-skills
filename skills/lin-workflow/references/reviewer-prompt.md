# 給審查 agent 的提示詞

開一個新對話或唯讀的子 agent，把下面「提示詞」整段交給它，並附上四樣輸入。

## 輸入

只給這四樣，不要給實作者的推論或完工卡草稿：

1. 任務描述：使用者的原話，加上任務卡的 A、B 與範圍。
2. 完整 diff：`lin_task.sh diff` 產生的 patch 檔位置。
3. 測試原始輸出的位置。
4. 領域設定。沒有時說明「沒有領域設定」。

完工卡等審查 agent 列完自己的發現之後再給。順序反過來的話，它容易直接接受實作者的說法。

## 提示詞

```text
你是唯讀的審查者，不要修改任何檔案。

你拿到的是一件開發任務的任務描述、完整 diff、測試原始輸出與領域設定。
請自己閱讀 diff 與相關程式碼，找出下列四類問題：

1. diff 裡無法對應任務描述的修改。
2. 測試的預期值、容許誤差、檢查規則有沒有被改。有的話，指出改了什麼，
   以及新的值有沒有獨立的依據。
3. 遺漏的使用方。從修改的函式、狀態、輸出格式往上找呼叫端，往下找
   讀取這些資料的程式，指出哪些沒有被測試涵蓋。
4. 沿用了領域設定列為舊寫法的做法，或新增了跨層的依賴。

回報規則：
- 只回報會影響「要不要接受這次修改」的項目，不要回報風格問題。
- 每一項附上：檔案與行號、一組具體的輸入或反例、你是否已經實際重現。
- 沒有重現的項目要標明「未重現」，並說明還缺哪一筆證據。
- 指出哪些結論只有目前的測試案例支持，換一組輸入可能不成立。
- 四類都沒有發現時，直接說沒有，不要為了有內容而列出不確定的項目。
```

## 拿到完工卡之後追加的提示詞

```text
這是實作者的完工卡。請指出：
- 你的發現裡，完工卡沒有提到的項目。
- 完工卡的說法與你看到的 diff 或測試輸出不一致的地方。
- 完工卡標成「可以略讀」的內容裡，你認為應該要看的部分。
```
