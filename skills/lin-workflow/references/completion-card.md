# 完工卡的格式與範例

完工卡是做完任務後貼回原對話的回覆，也是使用者審核的入口。使用者讀完第一段就要能決定：直接接受、打開某一段程式，或要求補證據。

## 格式

```text
【狀態】可快審／需要你判斷

改了什麼
  一兩句，描述使用者看得到的行為在修正前後的差別。
  改檔清單：按目的分組。

你需要看哪裡
  1. 判斷題。什麼條件會讓誰出錯、會看到什麼結果。位置：檔案:行號
  （沒有時寫「沒有待決事項」）

我自行決定了什麼
  1. 問題。採用的預設與理由。依賴它的修改。檢查點：<任務>/<標籤>
  （沒有時整段省略）

已經驗過什麼
  A：案例、修正前的值、修正後的值
  B：觀察的位置、修正前的值、修正後的值、用的是整包輸出比對或指定 B
  測試：命令、退出碼、案例數、原始輸出的位置
  獨立核對：做了哪幾項、結果
  沒有驗：範圍與原因

哪些可以略讀
  內容與略讀的理由。完整 diff：檔案位置
```

小任務可以把五個部分寫成一段，但狀態、A 與 B 的前後值、完整 diff 的位置不能省略。

## 範例

任務：`orders-api` 匯出訂單 CSV 時，「實付金額」欄位寫成折扣前的金額。

```text
【狀態】需要你判斷

改了什麼
  匯出的訂單 CSV，「實付金額」欄位原本寫入折扣前的金額，現在寫入折扣後的金額。
  改檔清單：
  - 匯出邏輯：src/export/order_csv.py（+6 -2）
  - 測試：tests/export/test_order_csv.py（+48）

你需要看哪裡
  1. 折扣為 0 的訂單，「折扣金額」欄位要寫 0 還是留空？我先寫 0。
     如果對帳人員的試算表把空白當成「沒有折扣活動」來篩選，寫 0 會讓這些訂單
     被算進折扣活動的筆數。位置：src/export/order_csv.py:87
  2. 這次修改涉及金額欄位，請確認「實付金額 = 訂單金額 - 折扣金額」符合財務的定義。
     運費目前不在這個欄位裡。位置：src/export/order_csv.py:81

我自行決定了什麼
  1. 折扣為 0 時欄位寫 0。理由：同一份 CSV 的運費欄位在金額為 0 時也寫 0。
     依賴它的修改：order_csv.py 第 85 到 88 行，以及一個測試案例。
     檢查點：csv-discount/q1-before 到 csv-discount/q1-after

已經驗過什麼
  A：訂單 1001（金額 1200、折扣 200）的實付金額欄位，修正前 1200，修正後 1000。
  B：訂單明細 API 回傳的 paid_amount。用 40 筆固定訂單分別跑起點版本與修正後版本，
     比對完整回應，40 筆完全相同（整包輸出比對）。
  測試：python -m pytest tests/export -q，退出碼 0，12 個案例通過。
        原始輸出：/tmp/lin-task/csv-discount/pytest.log
  獨立核對：四項都做了。子 agent 指出匯出檔的欄位順序沒有測試，已補一個案例。
  沒有驗：超過十萬筆訂單的匯出時間。這次沒有改查詢，判斷不受影響。

哪些可以略讀
  tests/export/test_order_csv.py 前 30 行是建立測試訂單的程式。
  完整 diff：/tmp/lin-task/csv-discount/task.patch
```

## 常見的寫法問題

| 不要這樣寫 | 改成 |
|---|---|
| 「修改了 `build_row` 函式的金額計算」 | 「實付金額欄位原本寫入折扣前的金額，現在寫入折扣後的金額」 |
| 「可能影響對帳，建議留意」 | 「如果對帳試算表把空白當成沒有折扣活動，寫 0 會讓這些訂單被算進活動筆數」 |
| 「測試全數通過」 | 「`python -m pytest tests/export -q`，退出碼 0，12 個案例通過，原始輸出在某檔案」 |
| 「B 沒有受影響」 | 「用 40 筆固定訂單跑新舊兩版，訂單明細 API 的完整回應相同」 |
| 把沒跑的測試省略不提 | 「沒有驗：某範圍。原因：某原因」 |
