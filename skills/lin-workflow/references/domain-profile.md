# 領域設定的格式

LIN 工作流本身不限定專案類型。每個專案在四個地方需要提供自己的內容，合稱領域設定。

## 放在哪裡

在 repo 的 `AGENTS.md` 或 `CLAUDE.md` 加一個標題含「領域設定」的段落。內容不多時直接寫在段落裡，內容多時段落只放一行指向另一個檔案。

```markdown
## LIN 工作流領域設定

見 docs/delivery-profile.md
```

## 四個項目

| 項目 | 要寫什麼 |
|---|---|
| 1．一定要人判斷的改動 | 通用類別（金額與結算、保存的狀態、機率或設定表、共用模組、對外協定、架構）在這個專案對應到哪些功能與檔案，以及這個專案額外的項目。 |
| 2．改了什麼要附什麼證據 | 依改動類型列出要固定的條件、要觀察的欄位，以及什麼情況要補更深的測試。 |
| 3．可重現的新舊比對 | 測試怎麼啟動、要固定哪些亂數與時間來源、需要哪些相依 repo 與版本。 |
| 4．認可的範例與已知舊寫法 | 推薦照著寫的實作、只為相容保留的寫法、待淘汰的寫法，各附位置與原因。 |

也可以列出這個專案可用的其他 skill，以及各自在什麼任務使用。

## 範例

以下是 `orders-api` 的領域設定。

```markdown
## LIN 工作流領域設定

### 1．一定要人判斷的改動

- 金額：src/pricing/ 與 src/export/ 裡所有金額欄位的計算。
- 保存的狀態：訂單狀態轉換（src/orders/state.py）、退款紀錄。
- 對外協定：/v1/orders 的回應欄位。前端與兩個合作夥伴都在使用。
- 共用模組：src/common/money.py。

### 2．改了什麼要附什麼證據

| 改了什麼 | 要附的證據 | 何時補更深的測試 |
|---|---|---|
| 金額計算 | 含折扣、含運費、金額為 0 三種訂單的前後值。 | 改到 src/common/money.py 時，另外跑退款與發票的測試。 |
| 訂單狀態 | 每個受影響的狀態轉換各一筆，包含重複送出同一個請求。 | 改到付款回呼時，用沙箱金流驗一次實際入帳。 |
| 匯出與報表 | 固定 40 筆訂單的完整輸出比對。 | 欄位順序或編碼有變時，請對帳人員確認試算表仍可匯入。 |

### 3．可重現的新舊比對

- 測試從 repo 根目錄執行：python -m pytest tests -q
- 要固定的來源：系統時間（測試用 freeze_time）、訂單編號產生器的種子。
- 固定資料：tests/fixtures/orders_40.json。
- 需要旁邊放同版本的 billing-service 才能跑整合測試。

### 4．認可的範例與已知舊寫法

- 推薦：金額一律用 src/common/money.py 的 Money 型別。範例見 src/pricing/discount.py。
- 只為相容保留：src/legacy/float_amount.py 用浮點數算金額，新程式不要呼叫。
- 待淘汰：直接在 handler 裡組 SQL。新的查詢寫在 src/repo/。
```

## 什麼時候補內容

領域設定的內容應該來自實際發生過的遺漏，不是事先猜測。這兩種情況發生時補一筆：

- 使用者退回完工卡，或接受之後才發現遺漏的影響。
- 做新舊比對時，發現一個之前沒固定住的亂數或時間來源。

agent 發現這類情況時在完工卡最後提出，由使用者決定要不要寫進領域設定。
