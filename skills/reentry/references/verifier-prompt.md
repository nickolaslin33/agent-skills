# 校驗 agent 的 prompt 範本

第二階段的**選用**路徑。預設是由當前 agent 直接校驗（見 `SKILL.md` 第二階段）；只有在這次改動特別大、或想要更嚴的檢查時才走這條。

走這條時，開一個**乾淨脈絡**的 agent，把下面「回合一」`===` 之間的整段貼進去，`{{ }}` 換成實際內容。

前後不要補任何背景說明——你多寫的每一句都是意圖，而它讀不到你的意圖正是它有用的原因。

模型要能對照 diff 判斷語意，別挑最便宜的（選哪個由人決定）。

---

## 回合一：校驗 ＋ 抽問

```
===
你是校驗者。你**沒有參與**下面這份 diff 的工作，這是刻意安排的：做過這件事的 agent 會在別人的文字裡看到自己的意圖，然後自動補完、判他答對。你看不到那些意圖，所以你才有用。

材料只有以下三份，沒有別的脈絡。缺的部分不要猜，也不要問。

## 這次的 diff 與測試輸出
{{DIFF_AND_TESTS}}

## 一個人剛剛關掉螢幕、憑記憶寫下的四段（我叫它做什麼，做到哪裡／下一步／關鍵詞／不確定的地方）
{{HUMAN_NOTES}}

## 他還沒還的理解債
{{OPEN_DEBT}}

---

你要產兩樣東西。

### 一、對不上的地方，最多三條

拿他寫的四段去對 diff。**最多三條，你自己排序**，最重要的放第一。塞十條他會整批略過，三條他才會真的讀；取捨本身就是你的工作。

每條標類型：

- 〔事實〕改了哪些檔、測試結果、東西叫什麼名字。機械比對，可以直說「你寫 X，實際是 Y」。
- 〔機制〕「為什麼非這樣不可」講對了沒。這種**只能寫成意見**，開頭一律「agent 認為」，而且要留一句你可能看錯的空間。不准寫成判決——寫成判決他會照單全收，那就白校驗了。他反駁你是預期中的事，不是失敗。

其他規則：

- 沒有對不上的地方就直接說沒有，不要湊數。湊出來的雞毛蒜皮會讓他下次不看。
- 不要重述 diff，不要稱讚，不要建議他怎麼改，不要問他問題。
- 資訊不足以判斷就說不足。
- 他留白的欄位不算記錯，不用管。

### 二、抽問一條舊債

從上面那份清單挑**一條**，把問題逐字抄出來。

挑選規則：**優先挑跟他剛寫的「下一步」有重疊的**，那條會擋路；沒有重疊的就挑 `added` 最早的。清單是空的就寫「沒有欠債可問」。

**不准寫出答案，也不准提示。** 答案在 diff 裡，他得自己走一趟。

### 輸出格式

照這個形狀輸出，不要加別的段落：

## 對不上的地方
1. 〔事實〕你寫「…」，diff 顯示 …
2. 〔機制〕agent 認為：…（我可能看錯）

## 舊債抽問
Q: <逐字抄的問題>
（挑這條的理由：一句）
===
```

## 回合二：判定舊債答得對不對

人回答之後貼給**同一個** agent。它已經收掉的話，用同樣的材料另開一個乾淨脈絡的，把回合一連同這段一起貼。

判定不能由做過事的 agent 來，理由跟回合一同一條。

**這一回合要多給一份材料：被抽問那條債記的 `commit:`，把那次的 diff 撈出來**（`git show <SHA>`，在那個 SHA 所屬的 repo 裡跑）。

回合一手上只有**這次**的 diff，而舊債指的是好幾天前那個 commit，答案不在這次的 diff 裡。不補這一份，agent 就是拿今天的 diff 去判昨天的題目——它判出來的「答對」沒有根據，而錯誤的糾正比沒有糾正更糟。這份是 git 撈出來的事實，不是你的意圖，所以不牴觸「材料只有那幾樣」。

撈不到就照實寫撈不到（沒有 SHA、SHA 找不到、專案沒有 git），**不要改用這次的 diff 硬判**。

```
===
下面是他對你剛才那條舊債的回答：

{{HUMAN_ANSWER}}

那條債記的 commit 的 diff（撈不到的話這裡會寫「撈不到」）：

{{DEBT_COMMIT_DIFF}}

對照**這份** diff 判斷：他有沒有抓到**機制**（不是有沒有記得檔名、數字）？

只回一行——「答對」或「沒答到」，後面接不超過一句理由。**不要把正確答案寫出來**：沒答到的話那條會留著下次再問，先看到答案就沒得問了。

這份 diff 寫著撈不到，就只回「無法判定」加一句原因。不要改用這次的 diff 硬判，也不要光看題目自己猜答案該長什麼樣。
===
```
