# 為什麼這樣設計

這份給「想改設計」的人看，不是執行時需要的。每條規則後面掛著它的依據，以及依據有多硬。

證據強度分四級：**(a)** 多研究重複驗證　**(b)** 單一研究或有爭議　**(c)** 實務界成熟流程但無對照實驗　**(d)** 從證據推的，文獻沒直說。

---

## 這個時間尺度上沒有「回憶」這回事

Resumption lag 隨中斷長度上升，但**在 13–23 秒之間就飽和**，58 秒和 38 秒沒有顯著差異。更精確的轉折在 5 到 15 秒之間：主導機制從記憶檢索換成從環境重建。**(a)**

**(d)** 推論：到「幾小時到一個週末」的尺度，記憶那條路早就斷了。回來時發生的百分之百是重建。所以交接紀錄不是提示，是自足的重建材料——寫給完全不記得的陌生人。

這條決定了整套設計的立場。如果哪天想把交接紀錄簡化成「幾個關鍵字提醒一下」，這裡就是反對意見。

---

## 為什麼第一階段不能看螢幕

判斷時只要看得到答案，延遲效應幾乎完全消失。**(a)**

看著 diff 評估自己懂不懂，等於沒評估。

## 為什麼沒有自評

讀文章時「分辨自己哪段懂哪段沒懂」的正確率約 **54.5%**，丟銅板是 50%。而且有個惡性循環**：愈沒懂的東西，愈判斷不出自己沒懂**。**(a)**（統合分析，115 篇、502 個效果量、N≈15,889）

所以整套繞開自評，改成憑記憶產出東西——**產不出來本身就是訊號**。

另外，問「你懂了嗎」這種是非題在人疲倦、題目難的時候最容易拿到隨口的「懂」，acquiescence 效應約 10%。**(a)** 收工正是疲倦的時候。

## 為什麼是「憑記憶生成」而不是「再讀一遍」

三個字：**延遲、生成、對題**。**(a)**

| 做法 | 對「判斷自己懂多少」的準確度 |
|---|---|
| 延遲摘要（讀完隔一段時間憑記憶寫一段） | **+0.210**（k=9） |
| 延遲關鍵詞（憑記憶寫 5 個） | **+0.184**（k=40） |
| 練習測驗（自己默答） | +0.169（k=47，證據量最大） |
| 自我解釋 | +0.179（k=7） |
| **立即**關鍵詞（讀完馬上寫） | +0.009，不顯著 |
| **讀現成整理好的關鍵詞** | **−0.096**，比什麼都不做還差 |
| 產生問題 | +0.042，不顯著 |

三個直接的後果：

- 「這次做了什麼」由人憑記憶寫，不是 agent 產——那是延遲摘要，效果最強的一項。
- 讀 agent 寫好的 summary 然後評分是**負的**。不要提供這種捷徑。
- 「不知道要問什麼就是沒懂」這個直覺**沒有實證支持**（產生問題 +0.042 不顯著）。不要拿它當偵測指標。

## 為什麼校驗者要用乾淨脈絡

**(d)** 這條是推論，沒有直接文獻。做過事的 agent 對「它做了什麼、為什麼」有強烈成見，使用者的文字沾到邊就會被自動補完然後判為答對。

間接支持：乾淨脈絡的 agent 讀 diff 的處境，跟使用者三天後回來的處境幾乎相同，而後者是這套機制真正要模擬的情境。

## 為什麼校驗結果要標「agent 認為」

有一批研究顯示人會過度信任 AI 的判斷，而且對 AI 信心愈高、回報的批判性思考愈少。**(b)**（自陳、橫斷面，不能推因果）

把糾正寫成斷言，使用者會照單全收——那就在更高一層重演了他原本的問題。降格成意見之後他要能反駁，而反駁的過程本身是自我解釋（+0.179）。**(a)**

## 為什麼最多三條

同時形成三個計畫的效果（d=.07）遠低於只形成一個（d=.41）。**(a)** 一次塞太多會互相稀釋。

## 為什麼「下一步」只寫一個、而且要具體

同上的 d=.41 vs .07。

線索的具體度有甜蜜點：**(a)**（642 個檢定的統合分析）

| 線索類型 | d |
|---|---|
| 只指定時間 | .25 |
| **時間＋地點** | **.46** |
| 時間＋地點＋怎麼做／做多久 | .24 |
| **使用者自己隨便指定的線索** | **.16**（全表最低） |

所以：兩個維度以上才有力，但綁在後面的動作只寫一個、不要寫成 SOP；而且**欄位不能開放自由發揮**——最後一列就是「讓人自己想格式」的下場。

## 為什麼有「若 X 則 Y」欄位

if-then 條件式格式的計畫（d=.43）明顯優於單純排程式的計畫（d=.29）。**(a)**

同時它對應醫療交班 I-PASS 的 contingency planning 區塊。**(c)**

---

## 為什麼欄位長這樣

主要抄 I-PASS，那是這批文獻裡實證最硬的：多中心研究、9 家醫院、10,740 次住院，導入後醫療錯誤降 **23%**、可預防不良事件降 30%，而且口頭交班沒有變長。**(a)+(c)**

| 欄位 | 對應 |
|---|---|
| 狀態一句話放最前面 | I-PASS 的 Illness severity；以及 NASA checklist 準則「最關鍵的排最前面，因為中斷隨時會發生」**(c)** |
| 下一步含具體對象與驗證方式 | I-PASS 的 Action list（to-do ＋ timeline ＋ ownership） |
| 若 X 則 Y | I-PASS 的 Situation awareness and contingency planning |
| 回來時覆述一次 | I-PASS 的 Synthesis by receiver；英國 HSE 交班指引的交叉查核 |

「寫值不寫『完成』」來自 NASA 的 checklist 準則：回「checked」不需要真的看，唸得出數值才代表看過。**(c)**

## 為什麼任務狀態要機器產、下一步要人寫

唯一一個直接做 A/B 的程式設計場景實驗：**用自動回顧型線索的人，任務成功率是只靠手寫筆記那組的兩倍**。開發者問卷（414 人）裡 Instant Diff 3.9 分排第一、Prospective Cues **2.7 分墊底**。**(b)**（只讀到摘要，未取得完整實驗設計）

正確的解讀不是「回顧型比較有效」，是**分工**：回顧型可以自動產、成本近乎零，該給工具；「下一步」產不出來、只有人知道，才是人必須手寫的部分。**(d)**

依據是「誰寫得出來」，不是「哪個有效」。

---

## 為什麼只有機制性的記錯算理解債

解釋深度錯覺（以為自己懂、一寫解釋就露餡）**只存在於機制性知識**，對事實、程序、敘事型知識弱或沒有。**(a)**

所以「為什麼非這樣不可」講錯了代表真的沒懂；檔名記錯只是記憶問題。

## 為什麼債的條目不寫答案

只讀題目跟答案（不自己默答）是 **−0.095**，而自己默答是 +0.169，兩者差 0.264。**(a)**

附上答案會製造「我懂了」的感覺，那正是要對付的東西。

## 為什麼還債寄生在校驗回合、而不是定期清算

提取練習證據量最大（k=47），而且延遲天然就長（幾天到幾週）。**(a)**

更關鍵的是**不需要新儀式**。「每週清算」是一個沒有觸發點的新動作，它會變成下一個不會做的事——而這整套機制解的就是這個病。**(d)**

---

## 停止引用這三個

- **「被打斷後要 23 分 15 秒才恢復」**——不在任何論文裡。追到最後是一次訪談，而且原意是「多久之後才回到那件工作」（中間穿插別的事），不是「回到之後多久恢復效率」。後者在同批文獻裡是**幾秒**的量級。
- **Zeigarnik 的記憶優勢**——59 篇統合分析，未完成／已完成的回憶量比值 **0.99**，等於沒有差別；排除原始資料後仍是 0.99。**(a) 的反面。**（但 Ovsiankina 效應撐住了：中斷任務的恢復率 67%。「會一直想回去做」有支持，「會一直記得」沒有。）
- **Dunning-Kruger**——被質疑是統計假象，而且這套機制根本不需要它。**(b)**

---

## 沒有證據的地方

誠實列出來，免得有人以為這些有實證撐著。

- **回來時的檢驗完全沒有實證支持**。有證據的檢驗點在離開時。「回來先覆述一次下一步」的依據是交班 protocol **(c)**，不是實驗。所以它被設計成只提示、不檢查。
- **幾小時到幾天尺度的恢復沒有任何受控實驗**。實驗文獻最長做到 30 秒到 1 分鐘，田野研究到「同一天」為止。跨夜、跨週末是空白。
- **「寫下一步」與「寫已完成」沒有頭對頭的實驗**。目前的分工是有理論支持、有間接證據、但沒有直接實證的假設。
- **多天等級的延遲是否還讓判斷變準，沒人研究過**。所有延遲研究的延遲都是分鐘等級。
- **讀 AI 產的 code 跟讀人寫的 code 有沒有差，沒有直接比較的研究**。現有研究不是操弄標籤（而非來源），就是缺人寫 code 的對照組。

## 驗收該量什麼

**錯誤率比反應時間敏感得多**：平均 4.4 秒的中斷讓序列錯誤率變三倍，而反應時間受到的影響小得多。**(a)**

**(d)** 所以用「回來後多久開始動手」當指標會低估損害。真正敏感的是**回來後前幾個動作的出錯率**。

自動可算又直接對應效果的是**校驗命中率的趨勢**——每次收工被指出記錯的條數，看月走勢。它免費，因為校驗回合本來就會產出這個數字。
